## 2. التقاطعات المتفق عليها (اعتمدها الـOrchestrator)
1. **الحالة قبل الرقم** في الترتيب النفسي والمعلوماتي — النتيجة غير المكتملة تعرض نص الحالة والسبب والعدّاد وزر الإكمال، وخانة النتيجة تبقى **بلا رقم نهائيًا** (وكيل 1+2+4، متوافق مع UX-D03/IX-D05).
2. **الحبر الداكن فوق التيراكوتا** (5.90:1) وليس الأبيض (3.12:1) — قاعدة إلزامية في كل تعبئة دافئة (وكيل 3+4، قياسات الملف 10).
3. **عزل bidi لكل سلسلة رقمية مختلطة** (`+42.50 د.أ`، `17/09/2026`، `#142`) — بدون عزل تقفز الرموز للجهة الخاطئة (وكيل 3+4+5).
4. **عدّاد الاكتمال "8 من 10" = progress affordance لا تحذير** — يحوّل الذنب إلى خطوة إنجاز (وكيل 1+2).
5. **كل رقم سالب: سبب محايد + إجراء واحد محدود** — الرقم الأحمر العاري يُقرأ اتهامًا (وكيل 1+2، Fixture C نموذجًا).
6. **حظر المقاصة** بين «لي عند العملاء» و«عليّ للموردين» — لا رقم يجمع الطرفين، ولا Green لأي منهما (وكيل 2).
7. **Micro Signal = Tint/Border حصريًا** — Fill يحوّله لافتة زخرفية (وكيل 3، تحذير الملف 02 §8).
8. **قوة QAB وزنية (Ink) لا كرومية** — يفك تعارض "حقل مهيمن واحد" مع Hero+Signal+QAB (وكيل 3).
9. **Visual Energy Budget كمقياس كمي**: تعبئة مشبعة=3، تينت=2، لمسة=1؛ ميزانية 5–6 (رئيسية) إلى 1–2 (سجلات)، وسقوف مساحة 35/15/8% (وكيل 3).
10. **IBM Plex Sans Arabic + أرقام tabular + عزل bidi** — الإبقاء على الأساس المؤكد (وكيل 3+5).
11. **بنية النموذج**: صفحات HTML مستقلة لكل شاشة، صفر مشاركة CSS بين الاتجاهات، حزمة QA خارجية عبر iframe، حالات كروابط عميقة `?state=&theme=&w=`، أصول محلية بلا CDN (وكيل 5 — تبني كامل).
12. **مصفوفة الإشارة الثانية** لكل الحالات الحرجة (نص + أيقونة/شكل دائمًا) (وكيل 4، IX-D05).
13. **المراجع البشرية** (أم محمد، عملية #142، درج المحل) جسر الثقة الأول — تُحفظ حرفيًا (وكيل 1).
14. **سقف 3 لمسات فعلية** لتسجيل البيع الشائع + معاينة أثر داخلية غير معترضة (وكيل 2).
15. **عدالة المقارنة**: أي إضافة معلوماتية لاتجاه تُطبق على الثلاثة (وكيل 2+5، الملف 06).

## 4. ما قبلته وما رفضته (موجز — التفصيل في decision-log.md)
- **قبول كامل**: 15 تقاطعًا في القسم 2 + قواعد C2 (C-05) + قاعدة C-01 + قرار C-06.
- **قبول مع تعديل**: توصية وكيل 5 بالبنية الهجينة (اعتمادها مع تعديل: قائمة الشعار داخل home.html كحالة `?sheet=menu` بدل صفحة مستقلة، مع إبقاء more.html مستقلة).
- **رفض مع توثيق السبب**: تغيير نصوص التجهيزات (C-02)، توحيد تسمية Hero (C-07).
- **تعليق للمالك**: حلقة التكلفة بعد البيع (C-03)، بدائل صياغة النصوص (C-02)، قيمة PIN النهائية (اقتراح: رمز الحماية (PIN)).

## 5. انحيازات تم رصدها وضبطها
1. وكيل 1 رتب C1>C2>C3 ثقافيًا — أُعيد تأطير الترتيب كفرضية (H3/H4) لا كتوصية نهائية؛ الاختيار النهائي عبر الروبريك الموزون فقط.

3. وكيل 5 افتراضيًا عدائي تجاه كل شيء — سيلزم لاحقًا تسجيل pass/fail موثق لكل فحص لا انطباعات.
