## Notes on the three "money-safety" rows

- **Tasks 10–12 (conflict / cancel / reverse)** are the audit-critical trio: they never
  auto-retry, never mutate data before an explicit confirmed success, and always leave a
  visible state row afterwards ("أُلغيت العملية" / "عُكست العملية" muted rows with the original
  sign preserved — history is not rewritten).
- **Tasks 3 and 13** share the prefill rule: the amount field is prefilled with the exact
  remaining balance (250.000 / 420.000) — a prefilled value is a *known* value, unlike task 4's
  empty expense field, which must show the "أدخل المبلغ" placeholder (state truth §4).
- **Task 6** is the only task whose primary components are list + PrimaryValueBlock rather than
  a sheet: settlement follow-up is a monitoring task; the sheet appears only when acting.
- Every failure path above ends in a **visible retry action** — the library never strands the
  user after a failure, and never retries automatically more than once.
