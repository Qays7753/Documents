# 01 — Current Work Lessons

**Delivery:** `micro-visual-product-concept-002`
**Stage:** 0 — lessons carried into the new concept

**Basis (honesty note):** `MicroPrimitives-anti-reference.html` was **not** available for inspection (see `00-SOURCE-INTAKE-REPORT.md`, S-8). The rows below are derived from (a) the orchestration prompt's own characterization of the `MicroPrimitives` composition and the current weak showcase, and (b) verified critique of the current Micro production screens in `Micro-Target-State-Design-Report.md` §4.13. Nothing in this table claims to quote the missing file.

| Current pattern | Why it feels generic, immature, empty, crowded, or unclear | What the new concept must do instead |
|---|---|---|
| Component-gallery composition (the `MicroPrimitives` showcase) | Reads as a design-system laboratory exposed to the end user: buttons, cards, and charts as exhibits rather than as an owner's day; no task has priority because nothing is a real task | Compose one believable owner reality — a working day with real orders, real debts, real cash — where every control exists to answer an owner question |
| Coding-style layout and showcase/lab controls inside the product frame | The frame looks like a development artifact (section numbers, toggles, labels), destroying trust in the product itself | A product-real phone frame: only owner-facing surfaces inside; all review controls (language, theme, width, motion) live strictly outside the phone |
| Card walls — every block an equal-weight boxed card | No reading order: 4 fact cards, 2 in-page units, optional modules all compete; the eye finds no entry point, so the screen feels both crowded and empty | A typographic reading order: one dominant figure where the screen's single question is answered, then list rhythm with hairline separation; cards only where a group is genuinely one unit (e.g. an order and its items) |
| Two in-page primary buttons plus the FAB («مالي» / «منتجاتي وخدماتي» units) | Unclear what the primary action is; competing CTAs feel like an unedited template | One primary per screen; the FAB «سجّل» is the global recorder; secondary destinations demote to a quiet links row |
| Finance opens with dense reading blocks (~13 top-level; dense «ما نعرفه الآن» text) | Decision is buried under reading; the screen feels like a compressed desktop ERP | Decisions first, reading second; ≤5 body blocks before the first collapsed layer; numbers gain meaning from hierarchy, not from text walls |
| Sale rows of 6–9 small lines with canned next-step text | Canned «الخطوة التالية: راجع أو صحح…» noise; long rows push other work off-screen; feels crowded and unedited | Rows ≤3 lines: who/what, status, amount; every detail behind one tap; next-step wording only when it is genuinely actionable |
| Inconsistent money language («دين مسجل (د.أ): 20.00», «الفرق 2.00 دينار», mixed placements) | Inconsistent units and placements read as careless with money — fatal for a financial product | One money language everywhere: `20.00 د.أ` (unit after number), ASCII digits, LTR-isolated, tabular alignment; signed deltas for change |
| Silent saves — money actions complete with no feedback | The owner cannot trust that the write happened; async work feels broken | Quiet completion: a receipt sentence with closure numbers («سُجّل بيع 20.00 د.أ — الكاش صار 165.00 د.أ»), a calm confirmation mark, then the surface settles; no confetti |
| Zero standing in for unknown (profit, opening balance, uncounted cash) | A fabricated 0.00 is a lie the owner will discover; trust collapses once | «—» with a road («سجّله»), «غير محدد بعد», «غير متاح» as first-class honest states with their own visual language (not just a color swap) |
| Notification-bell / alert-chrome patterns borrowed from generic apps | Attention chrome feels like a social app; the decision E-00.14 already rejected it — attention belongs in source rows | Attention lives inside source rows with action-specific labels («حصّل», «سلّم», «أكمل») and one quiet «اليوم» list on the opening screen |
| Generic Material/shadcn styling defaults (default radii, default elevation, default focus rings) | Instantly recognizable as a template restyle; no ownership of form | A deliberate form language owned by Micro: named radius scale, restrained elevation levels, hairline logic, measured focus treatment — documented as rules, not adjectives |
| Default-wallet and silent-discard behaviors (unallocated cash manufactured; typed amounts lost on sheet close) | Interaction feels immature — the product creates its own backlog and destroys input | Defaults that protect the fast path (wallet «الدرج»), and discard confirmation when input exists («في رقم مكتوب — تسجّله أو تتجاهله؟») |

*This table is the complete lessons register. It constrains the concept directions in Stage 1; none of the left-column patterns may return in the prototype.*
