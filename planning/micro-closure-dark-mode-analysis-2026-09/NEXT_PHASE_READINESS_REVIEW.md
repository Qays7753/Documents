## 5. Specific owner-decision impacts (mandated evaluations a–f)

**a. Row/Field convergence — where implementations diverge today; what breaks if journeys restructure lists/forms first.**
Verified: `<Row`/`<Field` appear only in `components/primitives/primitives.test.tsx`. Divergent surfaces: the finance-event card family (Finance/Statement/FinanceActivity/WalletLedger + EventsLayer/CorrectionsLayer — 13 `micro-finance-event` articles), the supplier-list row reuse (Suppliers, CashWallets wallets+entries, FinanceActivity rows), setting rows (Tools, ToolsIntegrity, Settings sections, LockSettingsCard), home fact/today/optional items (Home; `micro-home-fact` reused by Parties), loan/asset cards, owner-list rows, EstimateDetail list items, Schedule recurrence cards, AssetDetail event rows. Field side: `label.micro-field` + `EnglishNumberInput`/`LocalDateField` everywhere (430 hits/67 files). **What breaks:** a journey phase that merges/reorders lists first (e.g., unified activity, party-led collections, home re-layout) touches these families one by one; without a decided convergence order, each touch either (i) preserves bespoke markup (deepening divergence), or (ii) partially adopts `Row` (creating a third, mixed generation — the exact "second source of truth" the architecture forbids). Forms are the same story at 430 sites. → A5-11; recommend deciding wave order before list/form-heavy journeys; onboarding/finance-ordering journeys are not blocked.

**b. Commit-class expansion — where commit semantics appear without the commit class or confirmation path.**
The 8 (+1 conditional) `commit` usages verified: EventsLayer edit-confirm & restore-confirm (reason + preview), CorrectionPreview confirm (destructive when dangerous), G5DecisionPanel confirm, SettingsGuidedOpeningSection data-replacement confirm, OwnerEntitlement confirm, CashReversalEditor, InventoryReversalEditor, DeliveryReview. Commit semantics WITHOUT the class (all registered as deliberate `save`/`secondary`): OrderDetail one-tap transitions («ابدأ التنفيذ», «الطلب جاهز للتسليم», «استئناف التنفيذ بعد المراجعة» = `save`; «تسجيله دينًا» = `secondary`), AssetDetail revision (`save`) and — the sharpest case — disposal/write-off (`secondary`, A5-06), RepaymentSheet (`save`). **Impact:** any journey that reorders post-delivery or asset-retirement flows must know whether these acts gain confirmation paths; the registered decision (#7) is the right vehicle — it should explicitly cover the AssetDetail `secondary` pair and the OrderDetail debt-registration `secondary`, which sit below even the documented `save` floor.

**c. Link-ink role — where inline links/text actions appear; is a link-ink token/class needed?**
104 static `micro-text-action` usages across 37 non-test files (+ template/concat variants), carrying three semantics: navigation links (the majority — Home facts/roads, Finance road-lines, layer openers), state toggles (`aria-pressed`: FinanceActivity filters ×22, Statement ranges, LockSettingsCard options, CorrectionsLayer filter, EventsLayer show-all), and tabs (`role="tab"`: Finance view switch). Ratification should decide: link-only (migrate toggles to a chip/segmented pattern) vs link+pressed (extend the contract). The warning/withdrawal ink fate rides the same decision.

**d. Conditional feedback restructuring — where the ternaries live; how they complicate journey changes.**
Three coexisting classification regimes verified: (1) structured channels — CostEditor `message.kind`, AgreementContextPanel `saveState.kind`, ActualTimePanel `message.tone`, OwnerEntitlement `notice.tone` (safe); (2) `FeedbackNote` prefix regex `/^تم[ت ]/` + optional advisory — 8 consumers, 5 without advisory patterns (misclassification root of A5-01/A5-02); (3) preserved raw ternaries — 10 verified sites classifying by `message.startsWith/includes`: CashCount («انسجّلت»), Profile («حُفظ»), DraftEditor & Schedule («تم »), CostCalculator («حُفظ»), **CashDistribution («ان» — matches any message beginning with alef-nun; one new error string away from green-washing a failure)**, plus the structured-kind ternaries (ActualTimePanel, OwnerEntitlement, CostEditor, AgreementContextPanel). The register's "~22 surfaces" is plausible with the advisory-pattern sites included; I verified 10 raw + 8 FeedbackNote sites. **How they complicate journeys:** every flow merge copies one of three regimes; copy edits silently re-classify messages (prefix-dependent); the fragility is latent in exactly the surfaces (cash, schedule, drafts) a journey phase would touch first. → A5-14; the registered per-surface restructure should prioritize the prefix-sniffing sites and adopt one explicit channel (structure or explicit tone), never content-sniffing.

**e. Settings completion-copy — which surfaces show ✓-copy questions.**
Three surfaces carry a literal ✓ inside success message text: `pages/Settings.tsx:294` (export verified — the REGISTERED one), `presentation/cashCountMessages.ts:19` (cash-count settlement), `pages/CashDistribution.tsx:129–130` (allocation/cover). The registered decision says "the word is product-owned and frozen"; the register only names Settings. Post-W7, the Settings one renders inside InlineError (A5-01), i.e., alert marker + red ink + a ✓ in the text — a worse presentation than the registered "double glyph" description. **Impact:** the owner copy decision should be widened to all three surfaces and sequenced after (or with) the A5-01 classification fix, since the classification determines whether the ✓ doubles a marker or stands alone in error ink.

**f. FinanceActivity chip splitting — where the combined chip is; what journey work depends on it.**
Two distinct chip issues on this screen: (1) the **empty-state chip split** (registered, A4-L7): the single `EmptyState` (FinanceActivity.tsx:270–275) has no `state` slot, so "no activity in this range" does not distinguish *never recorded anything* (no-data) from *filter/range excludes everything* (no-results) — while Parties and Orders already implement the split; (2) the **per-row effect chip** (`micro-activity-effect micro-activity-effect-{in|out|quiet|pending}`) folds effect-class + tone into one chip — informational, not registered. **What depends on it:** any journey work that repositions the activity reader as the canonical "everything that happened" surface (Home's «افتح السجل الكامل» already funnels here), or that reuses its filter group elsewhere, inherits the unsplit void; the split decision is copy-first, then a one-line `state` slot adoption.
