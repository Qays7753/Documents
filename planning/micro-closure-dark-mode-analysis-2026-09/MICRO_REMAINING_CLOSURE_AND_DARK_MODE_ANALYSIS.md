## 1. Executive verdict

**The approved Light Integration scope is genuinely closed and verifiable. The next user-journey phase is NOT yet safe to start — it is one short remediation phase away.**

The integrity layer of the completion run survives adversarial re-verification: every SHA matches, the history is linear and fast-forward, the worktree is clean, the domain/application/storage layers are byte-untouched, the census claims (299 `<Button>` usages across 81 files, 8 `<ChoiceButton>`, 52/52 route matrix, 0 legacy classes for all 10 retired names) reproduce **exactly**, the run's test-count arithmetic is perfect to the test case (1,206 `it(` + 27 generated by `it.each` = 1,233), SHA256SUMS verifies 43/43, and the Documents mirror is byte-identical to the Micro run folder. The completion run's honesty discipline also holds: its NOT_RUN list is accurate and nothing material is hidden.

However, the five-agent analysis surfaced **60 findings** — **5 HIGH, 21 MEDIUM, 34 LOW** — of which **20 must close before a journey phase** and **10 require owner decisions**. The three most consequential discoveries, none of which were known to the completion run:

1. **Dark Mode is runtime-reachable today with a broken surface** (HIGH, A4-01). `App.tsx:13` runs `<ThemeProvider defaultTheme="system" switchable>` with visible toggles; the `.dark` block carries the retired v0 palette; and the entire W2 primitive layer is light-locked (`--vf-*` bindings never re-declared in dark) — quiet-button text computes to **1.05–1.18:1 (invisible)**. "Not activated" was a ratification statement, not a runtime state.
2. **A W7 fix introduced a success-rendered-as-error regression** (HIGH, A5-01). The `FeedbackNote` primitive classifies success only by the prefix `/^تم[ت ]/`; the Settings export-success and diagnostic-copy messages, three InventoryMaterials completions, and two DraftEditor advisories now render in **error ink with an alert glyph** (regression introduced by `db03aaf`).
3. **Interaction accessibility is untested** (HIGH ×2, A2-01/02): zero keyboard-event tests in all 205 test files, and one focus assertion in 1,624 tests. Escape-close, overlay focus traps, and the StartupGate journey have no behavioral evidence.

**Dark Mode recommendation: Option B** — keep the boundary, **close the missing semantic contracts now** (`styles/semantic-roles.css` + value-preserving retarget of primitive bindings, Wave R4), and implement the dark palette after the next journey phase. Mandatory companion: an immediate owner decision to **pin light** (D1) so the broken dark surface becomes unreachable.

**Bottom line:** the foundation is real and strong; the closure work that remains is small, well-scoped, and fully specified in NEXT_EXECUTION_PLAN.md (Waves R1–R4, all revertible, none touching domain logic or state words).

## 7. Dark Mode readiness and option comparison

Full detail in `DARK_MODE_READINESS_REVIEW.md` and `DARK_MODE_PARITY_MATRIX.csv` (63 rows × 11 columns).

### 7.1 Boundary state (verified)
- `.dark` block (`index.css:107-151`) re-declares **37 Micro runtime names** with the retired v0 palette (canvas `#1c1917`, brand `#d59172`, teal accents `#5ec0c1`/`#8fd5d6`, plus `--color-brand-pressed: #cc785c` which is on the test suite's own RETIRED list). **13 of 14 distinct dark hexes belong to no registry**; the design-token guard whitelists the `.dark` zone, so they pass silently.
- Theme mechanism: `ThemeProvider(defaultTheme="system", switchable)` → `.dark` class + `data-theme` + runtime meta theme-color rewrite. **Runtime-reachable today** — OS-dark devices load dark by default; AppHeader + Settings expose live toggles.
- Governance closed on paper: ADR-007, DARK_MODE_BOUNDARY.md (semantic-roles proposal + 6 owner-gate rules), register U-03; `styles/semantic-roles.css` confirmed **not implemented**.

### 7.2 Activation safety verdict: **PARTIAL-BROKEN / UNSAFE**
- **Resolves:** the alias-based shell + legacy feature CSS (~6,300 lines, `--color-*`) re-themes; dark text pairs pass (16.5/9.6:1).
- **Keeps light values:** the entire W2 primitive layer binds text/mark/fill roles directly to light-only `--vf-*` — all 8 button classes stay light islands; only the FAB (alias-bound) re-themes.
- **Breaks (static WCAG math):** quiet-button text **1.05–1.18:1 (invisible)**; commit-button boundary **1.18:1** (a high-consequence control dissolves); Row/Field/EmptyState titles **1.18:1**; captions/markers **1.81:1**; ghost **3.18:1**; InlineError **2.59:1**; even the adapting layer's hairlines are sub-floor (border 1.72:1, divider 2.19:1). Root cause: primitive text bindings violate the layer rule recorded in SOURCE_OF_TRUTH_MATRIX.md:57.
- **Contradictory:** teal returns as accent/focus/brand-text (violates U-02); dual clay identity (violates D-01); no `color-scheme` (native widgets stay light).

### 7.3 Parity matrix rollup (63 rows)
**29 PRESENT** (about half value-contradictory) · **9 PARTIAL** · **18 MISSING** (7 of them BROKEN-if-activated; includes all 8 button classes, the semantic-roles layer, the manifest twin, color-scheme) · **7 NOT-APPLICABLE** (charts have zero live consumers — U-16 floors recorded). Per area: buttons 0/8 present; state-semantics grammar survives but its surfaces don't; AUX shell adapts.

### 7.4 Standard contract status
`micro-standard-v2` is deliberately silent on themes (self-critique ×2). The minimum **product-agnostic** clarification it needs (A4-07 → D10, steward-gated): role names are theme-agnostic; contrast bindings are per-theme re-derivations; non-light themes require `color-scheme`; semantic roles must not encode theme-specific values. No Micro content, no dark palette, no second source.

### 7.5 Option comparison

| Dimension | **A — Implement Dark now** | **B — Boundary-ready + close semantic contracts now; implement after journey phase** | **C — Remove/deprecate `.dark`** |
|---|---|---|---|
| Closes user-facing breakage | Yes, fully | Only via the D1 pin-light companion (recommended) | Yes, by deletion |
| Palette decision burden | Forces an unratified dark palette NOW (13 unregistered hexes; Standard has no theme contract — second-source risk) | Defers palette ratification to its own owner gate after the Standard clarification | Removes the question entirely |
| Journey-phase interaction | Journey rework happens AFTER dark lands (screens reshaped twice) | Journey builds on stable semantic contracts; no light-only debt accrues | Same as B for contracts; loses the working alias-layer dark for legacy surfaces |
| Strategy compliance | Same components, but palette improvisation risks violating single-source | Same primitives; separate semantic mapping; additive rollback — fully compliant | Compliant but destroys the documented boundary structure (ADR-007) and churns guards asserting `.dark` existence |
| Rework risk | High (palette + parity testing before screens stabilize) | Lowest — the only option that **shrinks** future rework | Medium (removal then re-addition) |
| Sequencing authority | Contradicts ADR-007/U-03 sequencing | **Is** the ADR-007 sequencing | N/A |

### 7.6 Recommendation: **Option B**
With two mandatory companions:
1. **D1 (immediate):** owner decision to pin light (`defaultTheme="light"`, `switchable={false}` or hidden toggle) until the dark wave — making the broken surface unreachable. (If the owner instead accepts reachable dark, dark parity enters every journey test matrix — a much larger immediate burden on an unratified palette.)
2. **Wave R4 (before the journey phase):** land `styles/semantic-roles.css` (layer 2.5) and retarget `primitives.css` text/mark/fill bindings to semantic roles — **value-preserving in light** (computed styles unchanged), zero TSX changes, 299 Buttons inherit automatically, single-commit rollback. This stops new screens from accruing the light-only `--vf-*` binding pattern.

The full dark implementation (owner-approved palette, parity matrix, PWA twins, color-scheme, non-color semantics, independent rollback, owner gate) then runs as its own wave **after** the journey phase, exactly as ADR-007/U-03 encode.
