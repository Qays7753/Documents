## 1. Executive verdict

**The quantitative claims are unusually accurate; the qualitative coverage claims are systematically stronger than the evidence.**

- Every numeric claim I could statically verify reconciles **exactly**: root suite 35 files / 391 tests; client suite 170 files / 1,233 tests (1,206 `it(` + 27 generated by 6 `it.each` blocks); test-focus 205 files; runtime-cycles 259 production files; text-density PAGES list = 52; matrix 52 rows = 52 filesystem pages; 0 `.only/.skip`; 15 QuickActionSheet tests. The pipeline stages are all **real and wired into `pnpm check`** (REPRODUCIBLE-CONFIG).
- However, whole interaction dimensions have **zero automated evidence**: no keyboard-event test exists anywhere in the tree (no `userEvent.keyboard`, no `fireEvent.keyDown` — 0 hits); exactly **one** focus assertion in 1,624 tests; no contrast computation; no safe-area test; no overlay focus-trap test. The "Escape closes the sheet", "reduced-motion verified at DOM level", and the 360/430 width-matrix claims rest on manual capture-run notes or CSS-string assertions, not on automated tests.
- Page-render coverage is **39 of 52 pages (75%)**, not the 40/52 the matrix implies: `MIGRATION_MATRIX.csv` row 43 labels `Schedule` (1,027 lines — one of the largest pages) as `journey/dom`, but **no test imports or renders `pages/Schedule`**. The 12 `none-found` routes are honestly declared, but FINAL_TEST_RESULTS.md:32's "covered by typecheck/lint/the general suites" overstates what typecheck/lint do (they never execute page code).
- The NOT_RUN list is **honest and matches the tree** (no reduced-motion/RTL-specific/scaling/device tests exist). The one place it understates: EXECUTION_REPORT §7.F says "RTL/bidi/Escape/reduced-motion **verified at DOM level**" — reduced-motion is only a CSS-source string assertion, and Escape is only a manual note in `capture-log.json`.

**Verdict:** the run's mechanical/test infrastructure is genuinely strong (guards are self-testing, journeys use real services + memory stores, counts are exact), but accessibility interaction (keyboard, focus, contrast) and 13 never-rendered pages are the real open surface. None of this invalidates the Light-scope closure; several claims need wording corrections and a small set of tests before the next phase builds on them.

## 6. Test-quality findings (mandate item 5 — 15 files sampled)

**Overall: the suite is better than average.** Journeys use real services over `MemoryLocalStore` (no mocked stores in the dom suites), race-free gated async (`Home.dom.test.tsx:136-161`), failure injection (`ErrorBoundary.dom.test.tsx:116-135`), and self-testing guards that run the real ESLint engine (`check-layer-boundaries.test.mjs:38`). The issues are concentrated and specific:

**(a) Class-name/implementation assertions without behavior** — legitimate on primitive contracts (the class IS the contract; e.g. `primitives.test.tsx:71-79` save/create classes), but these cross into pseudo-behavior:
- `primitives.test.tsx:320-357` — entire describe block reads `primitives.css` as a string and asserts substrings. Titles claim behavior ("reduced motion collapses nonessential movement" :348; "buttons carry the 48px control height" :336) but the assertions would pass with an empty rule body as long as the selector/text exists.
- `U09.css.test.ts:17-35` — same pattern for touch targets ("min-height: 48px" string match).
- These are fine **as guards**; they are misleading **as titles**.

**(b) Weak selectors:**
- `U001.dom.test.tsx:119` and `EventsLayer.familyGuard.dom.test.tsx:119` — `document.querySelectorAll("article.micro-finance-event")`: global class queries (mitigated by `within(row)` scoping and behavioral assertions, but coupled to CSS class names).
- `primitives.test.tsx:37,73,77` etc. — `container.querySelector(".micro-prim-chip")` (legitimate for primitives, listed for completeness).

**(c) Census-style tests (existence/count, not behavior):**
- `primitives.test.tsx:228-232` — **vacuous test**: "knowledge tones are not valid stripe tones (type-level contract)" creates a local `["success","error","info"]` array and asserts `toHaveLength(3)`. It tests nothing about the actual `stripeTone` type; the comment admits it. Would keep passing if the product broke.
- `QuickActionSheet.test.ts:5-47` — asserts the static `actionItems` array (existence, order, descriptions). Legitimate menu-contract census, but no user flow.
- `app/navigation.test.ts` — nav table census (fine for a table contract).

**(d) Skipped/todo tests: none.** 0 `.skip(`/`.todo(`/`.only(` across all 205 files — matches the test-focus claim exactly.

**Would tests keep passing if the product broke?** For: reduced-motion rules being emptied (yes — string test), stripe width regressions beyond the matched string (yes), Escape-close breaking (yes — no test), focus trap breaking (yes — no test), Schedule page crashing on render (yes — never rendered), the 12 none-found routes crashing (yes — never rendered).
